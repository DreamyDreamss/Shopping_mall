## 변경 컨텍스트 (SR-211)
> 이 story는 변경요청 **SR-211 — SR-211** 에서 나왔다. 신규 구축이 아니라 **기존 동작의 변경**일 수 있으니, 바꾸지 않아야 할 것을 먼저 확인하라.

### 확정된 요건 문답 9건 — 이대로 구현한다(재해석 금지)
- **이번 SR에서 하는 것과 명시적으로 빼는 것은 무엇인가?** — 포함: 전일(D-1) 주문의 일자별 집계(주문건수·주문총액·취소건수·취소금액) 1행 생성과 재실행 멱등. 제외: 집계 조회 화면·API, 월/주 단위 집계, 상품별·회원별 분해.
- **반드시 유지돼야 하는 기존 동작(회귀 범위)은 무엇인가?** — 주문 조회·목록·상세·CSV 내보내기의 응답과 화면은 그대로여야 한다. 배치는 읽기만 하고 orders/order_items를 수정하지 않는다.
- **기존 클라이언트와의 하위호환이 필요한가?** — 기존 API에 변경 없음 — 배치 전용 신설이라 하위호환 이슈가 없다. 수동 실행 진입점만 내부용으로 둔다(외부 공개 아님).
- **오류 응답 계약(코드·메시지)은 무엇인가?** — 배치는 HTTP 계약이 아니다. 실패는 로그와 종료코드로 보고한다 — 0=성공, 1=집계 실패(그날 행을 남기지 않는다). 부분 집계는 금지.
- **배치 실행 주기와 재실행(중복 실행) 멱등성은?** — 주기: 매일 새벽 1회(전일 대상). 멱등: 집계 일자를 기본키로 두고 같은 날짜를 다시 돌리면 기존 행을 덮어쓴다(중복 행 생성 금지). 집계는 한 트랜잭션에서 지우고 다시 넣는다 — 중간 실패 시 그날 행이 남지 않는다.
- **타 도메인 테이블·집계(정산·통계류)에 파급이 있는가?** — 없음
- **기존 데이터 이관·백필이 필요한가?** — 필요 — 집계 테이블을 새로 만든다(order_daily_stats). 기존 행 백필은 하지 않는다(과거분은 필요할 때 날짜를 지정해 재실행한다).
- **변경 대상 화면이 전부 나열됐는가? (누락 화면 없음 확인)** — 화면 변경 없음 — 이번 SR은 배치만이다. 집계 결과를 보는 화면은 별도 SR로 뺀다.
- **빈 값·오류 상태의 화면 표기는 무엇인가?** — 해당 없음(화면 없음). 대상 주문이 0건인 날도 0으로 채운 집계 행을 남긴다 — 행이 없는 것과 0건인 것은 다르다.
