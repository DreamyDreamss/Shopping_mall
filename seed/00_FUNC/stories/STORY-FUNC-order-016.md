### 확정된 요건 문답 8건 — 이대로 구현한다(재해석 금지)
- **이번 SR에서 하는 것과 명시적으로 빼는 것은 무엇인가?** — 포함: 리뷰 테이블 신설(product_reviews), 리뷰 등록 API, 리뷰 목록 API, 상품 상세 화면의 리뷰 목록·등록 폼. 제외: 리뷰 수정·삭제, 이미지 첨부, 신고·차단, 평균 별점의 상품 목록 노출.
- **반드시 유지돼야 하는 기존 동작(회귀 범위)은 무엇인가?** — 상품 상세·목록의 기존 응답과 화면은 그대로여야 한다. 리뷰가 0건이어도 상품 상세는 종전과 같이 렌더된다(리뷰 영역만 빈 상태).
- **기존 클라이언트와의 하위호환이 필요한가?** — 기존 상품 API 응답 스키마는 바꾸지 않는다 — 리뷰는 별도 엔드포인트로 뺀다. 상품 상세 응답에 리뷰를 끼워 넣으면 기존 클라이언트의 파싱이 깨진다.
- **오류 응답 계약(코드·메시지)은 무엇인가?** — 별점이 1~5 밖이면 400 + 코드 ORD-4004, 메시지에 허용 범위를 담는다. 같은 회원이 같은 상품에 두 번 쓰면 409 + 코드 ORD-4090. 없는 상품이면 404 + ORD-4041. 성공은 201 + 생성된 리뷰 1건.
- **타 도메인 테이블·집계(정산·통계류)에 파급이 있는가?** — 없음
- **기존 데이터 이관·백필이 필요한가?** — 신규 테이블만 만든다(product_reviews). 기존 행 백필 없음. PK는 자동증가 review_id, (product_id, member_id) 유니크 제약으로 중복 등록을 DB가 막는다 — 애플리케이션 검사만 두면 동시 요청에서 뚫린다.
- **변경 대상 화면이 전부 나열됐는가? (누락 화면 없음 확인)** — 상품 상세(UIS-ORD-004) 한 화면만이다. 상품 목록·주문 화면은 건드리지 않는다.
- **빈 값·오류 상태의 화면 표기는 무엇인가?** — 리뷰 0건이면 '아직 등록된 리뷰가 없습니다'를 표시하고 등록 폼은 그대로 둔다. 등록 실패 시 폼 위에 사유를 띄우고 입력값은 유지한다(다시 쓰게 하지 않는다).
