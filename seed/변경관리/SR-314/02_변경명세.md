# SR-314 변경명세

## AS-IS → TO-BE 비교

### SCH-ORD-005 (products) — docs/05_설계서/order/SCH/SCH-ORD-005.md

- AS-IS: `image_url`(VARCHAR(300), NULL 허용)은 "런타임 쓰기 경로가 없다(시드로만 채워짐)" — 비즈니스 주의사항에 "주문·정산·통계 등 타 도메인 조인·집계는 이 두 컬럼(`list_price`·`image_url`)을 읽지 않고 `price`만 쓴다"로 명시.
- TO-BE: 적재기(SR-314.2)가 카탈로그 매니페스트의 `image`(예: `images/SKU-xxxx.jpg`)를 근거로 `image_url`을 UPSERT로 기록 — "런타임 쓰기 경로 없음" 불변식이 적재기 실행 시점부터 깨진다. `image_url`이 가리키는 실제 파일은 `shop.product-image-location` 설정 경로(예: `{{WS}}/_lab/catalog/images/`)에서 `/images/products/**`로 서빙되며, 설정이 없거나 파일이 없으면 기존 SVG 폴백을 유지한다.

- AS-IS: `list_price`(BIGINT, NULL 허용)도 동일하게 "런타임 쓰기 경로 없음(시드로만 채워짐)".
- TO-BE: 적재기가 매니페스트의 `list_price`(널 허용)를 UPSERT로 기록. `price`와 무관하며 표시 전용이라는 기존 의미는 유지(화면의 할인 계산 로직 변경 없음).

- AS-IS: `sale_yn`(CHAR(1), 기본 'Y')은 주문 생성 검증([[INF-ORD-005]])의 대상이며, 쓰기 주체는 [미상](스펙 문서에 명시 없음 — 시드/기존 로직으로 추정).
- TO-BE: 적재기가 매니페스트에서 빠진 기존 적재 상품을 삭제하지 않고 `sale_yn='N'`으로 내리는 쓰기 주체로 추가된다(주문 이력 보존 목적). 코드값 의미(Y=판매중/N=판매중단, 주문 생성 시 'Y' 필수)는 변경 없음 — 쓰기 경로만 추가.

- AS-IS: `price`(BIGINT, NOT NULL)의 쓰기 주체는 [미상](스펙 문서에 명시 없음).
- TO-BE: 적재기가 매니페스트의 `price`를 UPSERT 대상으로 기록.

- AS-IS: UPSERT 키(멱등 판정 기준)에 대한 언급 없음 — PK는 `sku`(VARCHAR(20)).
- TO-BE: 적재기 멱등 키는 상품 `sku`(기존 PK와 동일), 카테고리 `code`, 브랜드 `code`(모두 SR-314 확정 문답 근거 — 코드 기준 키). 같은 매니페스트를 반복 적재해도 행 수·값 불변.

- AS-IS: `category_id`·`brand_id`(products 테이블 FK 컬럼), `PRODUCT_IMAGES`(MAIN 이미지), `PRODUCT_TAGS` 테이블·컬럼 정의는 SCH-ORD-005 문서에 없음.
- TO-BE: [미상] — 확정 문답은 "적재 대상 = SR-313의 CATEGORIES·BRANDS·PRODUCTS(category_id·brand_id)·PRODUCT_IMAGES(MAIN)·PRODUCT_TAGS"라고 전제하나, 이 컬럼·테이블의 스펙은 이번 SR의 근거 파일(SCH-ORD-005)에 실려 있지 않다. SCH-ORD-005 갱신(또는 별도 스펙 신설)은 승인 뒤 AIDD 재동기화의 몫.

- AS-IS: `tv_product`·`installment_months`·`free_shipping`·`card_discount_pct` 컬럼은 SCH-ORD-005에 없음(products 테이블 컬럼 목록에 미기재).
- TO-BE: 적재기가 매니페스트에서 값은 읽되 저장하지 않는다(SR-318 컬럼 신설 전까지 버림) — 성공 응답의 `ignoredFields[]`에 표기. 테이블 스키마 변경 없음(SCH-ORD-005 컬럼 목록 불변).

### INF-PRD-002 — 카탈로그 적재 관리 명령 (SR-314.1)

- AS-IS: 없음(신규) — 기존 스펙 파일이 존재하지 않는다(`docs/05_설계서/**/INF-PRD-*` 미존재 확인).
- TO-BE: `POST /api/admin/catalog/reload` 신설. 인가: 무키 401, 회원 키 403(기존 인가 규약 재사용), 관리자 API 키만 허용. 요청 본문 [미상](요구사항·확정 문답에 본문 스키마 명시 없음 — 매니페스트 경로는 `shop.catalog.manifest` 설정 키로 서버 측 결정되는 것으로 보이며, 요청 파라미터 여부는 [미상]). 응답: 매니페스트 파일 없음/파싱 실패 시 400 `PRD-4001`(메시지에 경로·사유 포함), 성공 시 200 `{loaded, skipped[{sku, reason}], ignoredFields[]}`.

### BAT-PRD-001 — 카탈로그 매니페스트 적재 배치 (SR-314.2)

- AS-IS: 없음(신규) — 기존 스펙 파일이 존재하지 않는다.
- TO-BE: `shop.catalog.manifest` 설정 키가 있을 때 lab 프로파일 기동 시 1회 옵트인 적재(주기 실행 없음). 대상: `{{WS}}/_lab/catalog/catalog.json`(최상위 `source`·`categories[]`·`brands[]`·`products[]`). 카테고리 `{code, name, source_id?, children[]}`(대분류 9 → 중분류), 브랜드 `{code(KB001…), name}`, 상품 `{sku(SKU-3001…), name, brand, category, price, list_price|null, stock_qty, sale_yn, description, tags[], image, tv_product, free_shipping, installment_months|null, card_discount_pct|null, source_id, source_url, author, license}`. UPSERT 멱등(코드 기준 키). 행 단위 거부(필수 누락·중복 sku·이미지 파일 없음)와 요약 보고. 기존 SKU-1001~1004는 건드리지 않는다. 매니페스트에서 빠진 기존 적재 상품은 삭제하지 않고 `sale_yn='N'`으로만 내린다.

## 제외(변경 없음 명시)

- 이미지 파일의 저장소 커밋·소스 트리 복사 — 요구사항 범위에서 명시 제외(사내 로컬 한정, 공개 저장소 반입 금지).
- 마이그레이션 SQL의 상품 데이터 하드코딩 — 매니페스트 적재로 대체, SQL 하드코딩 금지(요구사항 명시).
- 관리자 등록 화면(SR-279) — 별도 SR 범위, 이번 SR은 적재 명령·배치만 다룬다.
- 외부 사이트 이미지 핫링크 — 제외(로컬 파일 경로 서빙만).
- 리사이즈·WebP 변환(SR-291) — 제외.
- 리뷰·평점 데이터 — 제외(가짜 후기 금지, SR-304 결정 재확인).
- 기존 `/images/products/*.svg` 경로·SVG 폴백 로직 — 변경 없음(설정 미존재 시 그대로 유지).
- 기존 SKU-1001~1004의 값·장바구니·주문·체크아웃 API 계약 — 변경 없음(적재기가 이 SKU를 건드리지 않음).
- 타 도메인 테이블·집계(정산·통계) — 영향 없음(상품 도메인 테이블만 사용, 주문·장바구니는 sku 참조라 무관).
- 기존 데이터 이관·백필 — 없음(SR-313이 만든 스키마를 채우는 것이 이 SR의 산출물이며 기존 행 백필은 하지 않음).

## 회귀 범위

- 기존 SKU-1001~1004의 값·장바구니·주문·체크아웃 흐름 불변(적재기는 이 SKU를 건드리지 않는다).
- 설정 키(`shop.product-image-location`, `shop.catalog.manifest`)가 없으면 기동 동작이 지금과 완전히 같다(적재 없음·이미지 SVG 폴백).
- 기존 `/images/products/*.svg` 경로 유지.
- 기존 테스트 전부 통과.
- 기존 엔드포인트 계약 불변(추가만 — 신규 `POST /api/admin/catalog/reload`와 이미지 정적 경로).

## 롤백 요지

`POST /api/admin/catalog/reload` 및 옵트인 기동 적재를 비활성화(설정 키 `shop.catalog.manifest` 제거 또는 미설정)하고 `shop.product-image-location` 설정을 제거하면 이미지 서빙은 기존 SVG 폴백으로, 카탈로그 적재 동작은 무동작 상태로 각각 되돌아간다. 적재기가 UPSERT로 기록한 `products.image_url`·`list_price`·`price`·`sale_yn`과 SR-313 산출 테이블(CATEGORIES·BRANDS·PRODUCT_IMAGES·PRODUCT_TAGS)의 적재 행은 배치 역순으로 별도 정리(삭제 또는 이전 값 복원)가 필요하나, 그 절차는 이번 변경명세의 범위 밖이며 [미상](롤백 시 데이터 정리 절차는 확정 문답에 명시되지 않음).
