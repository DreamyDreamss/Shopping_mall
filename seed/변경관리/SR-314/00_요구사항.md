# SR-314 — 카탈로그 적재·외부 이미지 서빙 — catalog.json(kshop 실제 상품) 적재기

> 생성: 2026-09-19 · 출처: 로컬(SpecLens) · 계획 `_lab/plan/new_srs.json` N06 · 에픽 상품 · 유형 DB+배치 · Wave 1
> 벤치마크: KT알파쇼핑 — `_lab/plan/benchmark_ktalpha.md`(스크린샷 `_lab/plan/bench/`), 전체 계획 `_lab/plan/ECOMMERCE_PLAN.md`

## 요구 요지

{{WS}}\_lab\catalog\catalog.json(KT알파쇼핑 실제 상품·카테고리·브랜드)을 기동 시(옵트인) 또는 관리 명령으로 적재하는 멱등 적재기를 만들고, 상품 이미지는 소스 트리로 복사하지 않고 외부 경로({{WS}}\_lab\catalog\images)를 앱이 /images/products/** 로 서빙한다. 카탈로그 교체가 코드 변경 없이 된다.

## 배경

상품 4종과 SVG 대체 이미지로는 목록·검색·카테고리 탐색을 실물처럼 확인할 수 없다. 이미지 자산 규칙: KT알파쇼핑 상품 이미지는 사내 로컬 한정이라 모듈 git·스냅샷(공개 저장소로 나감)에 들어가면 안 된다. 이미지를 shop-api 소스 트리로 복사하지 않고, 외부 경로를 설정 키(shop.product-image-location=file:{{WS}}/_lab/catalog/images/)로 받아 앱이 /images/products/** 로 서빙한다. 설정값이 없거나 파일이 없으면 기존 SVG 대체 이미지로 폴백한다. 상품 데이터는 마이그레이션 SQL에 하드코딩하지 않고 매니페스트 한 곳을 정본으로 삼아 다시 적재할 수 있어야 한다.

## 범위

- 포함:
  - ① 이미지 서빙 — 설정 키 shop.product-image-location(예: file:{{WS}}/_lab/catalog/images/)을 Spring 정적 리소스 핸들러로 /images/products/** 에 매핑, 설정이 없거나 파일이 없으면 기존 SVG 폴백, 공개 GET ② 매니페스트 계약 확정(최상위 categories[]·brands[]·products[]; 상품 sku·name·brand·category(소분류 코드)·price·list_price·stock_qty·summary·origin·images[]·notices{}·tags[]·선택 tv_product·installment_months — 실제 catalog.json 필드가 다르면 실제 파일을 기준으로 계약을 문서화) ③ 적재기 — 설정 키 shop.catalog.manifest 경로를 lab 프로파일 기동 시 옵트인 적재 또는 관리 명령(관리자 API/CLI)으로 실행, UPSERT 멱등, 필수 누락·중복 sku·이미지 없음은 행 단위 거부 후 보고, 기존 4개 sku 유지.
- 제외:
  - 이미지 파일의 저장소 커밋·소스 트리 복사, 마이그레이션 SQL의 상품 데이터 하드코딩, 관리자 등록(SR-279), 외부 사이트 이미지 핫링크, 리사이즈·WebP(SR-291), 리뷰·평점 데이터(가짜 후기 금지 — SR-304 결정).

## 수용 기준

- [ ] 적재 후 대분류 9개의 3단 트리, 브랜드 10개 이상, 판매중 상품 50개 이상이 조회된다(실제 catalog.json 건수 기준으로 확정)
- [ ] 같은 매니페스트로 두 번 적재해도 행 수·값이 변하지 않고, 매니페스트를 바꿔 다시 적재하면 코드 변경 없이 카탈로그가 바뀐다
- [ ] 잘못된 행(필수 누락·중복 sku·이미지 없음)은 건너뛰고 사유와 함께 요약 보고되며 나머지는 적재된다
- [ ] shop.product-image-location이 설정되면 /images/products/{sku}.jpg가 외부 경로 파일로 200 응답하고, 설정이 없으면 기존 SVG가 서빙된다
- [ ] shop-api 소스 트리·git 추적 파일·마이그레이션 SQL에 kshop 이미지나 상품 데이터가 없다(git ls-files 검사)
- [ ] 기존 4개 sku의 장바구니·주문 이력이 깨지지 않는다
