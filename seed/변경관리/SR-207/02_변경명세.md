# SR-207 변경명세

## AS-IS → TO-BE 비교

### INF-ORD-002 (GET /api/members/{memberId} — 회원 상세 조회)

- AS-IS:
  - 요청: PathVariable `memberId`(string, 필수) 단일 파라미터.
  - 응답(200): `memberId`, `memberName`, `grade`, `phone`, `createdAt`, `recentOrders[]`(각 원소: `orderNo`, `orderState`, `totalAmount`, `orderedAt`).
  - 비즈니스 규칙: `del_yn = 'N'` 상시필터(탈퇴 회원 조회 시 404) / `recentOrders`는 `ordered_at DESC, order_no DESC` 순 상위 5건 고정(`RECENT_ORDER_LIMIT`) / 주문 없으면 `recentOrders`는 빈 배열(`null` 금지) / 취소 주문(`CANCELED`)도 `orderState` 값에 포함되어 있어 별도 제외 로직 없음.
  - 오류: 404(회원 없음/탈퇴 회원). 401/5xx는 스펙 파일에 명시 없음 — 공통 처리로 추정([미상], 파일 근거 없음).
  - 화면 연결: `screens: []` — 이 API를 소비하는 화면 명세 없음.
  - `srs-f: [TBD]` — 대응 SRS-F 미정.
- TO-BE:
  - 요청: 변경 없음(필드 추가만 하기로 확정 문답에서 답변됐으나, 이번 SR 범위인 회원 상세 화면·최근 주문 5건 표시에는 요청 파라미터 추가 요구가 없음).
  - 응답(200): 필드 구성·타입·정렬·5건 고정·취소 주문 포함 규칙 모두 **그대로 유지**(요구사항 "API 응답 계약은 바꾸지 않는다", 확정 문답 `api_compat`: "필요 — 필드 추가만"이나 이번 SR에서 실제 필드 추가 요구는 없음).
  - 비즈니스 규칙: 변경 없음.
  - 오류: 변경 없음(확정 문답 `api_error`: 기존 오류 계약 그대로 — 404/401/5xx 공통 배너, 신규 오류 코드 없음).
  - 화면 연결: `screens: []` → 신규 화면(회원 상세/마이페이지, UIS 신규 채번, ID [미상])이 이 API를 소비하도록 **추가**. INF-ORD-002 본문의 `screens` 필드 갱신 필요(스펙 현행화는 본 변경명세의 스코프 밖 — 승인 후 AIDD 재동기화에서 처리).

### 신규 UIS (회원 상세/마이페이지 화면, ID [미상])

- AS-IS: 없음(신규 화면).
- TO-BE:
  - 데이터 소스: INF-ORD-002 응답의 `recentOrders`를 그대로 사용(신규 API 없음).
  - 표시 항목: 최근 주문 5건을 최신순(API 정렬 그대로: `ordered_at DESC, order_no DESC`)으로 나열 — 항목별 `orderNo`(주문번호), `orderedAt`(일시), `orderState`(상태), `totalAmount`(금액).
  - 빈 상태: `recentOrders`가 빈 배열이면 "최근 주문 없음" 문구 표시.
  - 취소 주문: `orderState = CANCELED`도 목록에 포함(현행 API 규칙 그대로, 별도 필터 없음).
  - 상호작용: 주문번호(`orderNo`) 클릭 시 UIS-ORD-002(주문 상세)로 이동.
  - 오류 상태: 회원 없음(API 404) → 화면은 친화 안내 표시. 미인증(401) → 표준 처리. 조회 실패/5xx → 기존 공통 오류 배너.
  - 권한: SR-204 전역 정책 그대로 적용(관리 자원) — 이 화면 전용 권한 규칙 신규 추가 없음.

## 제외(변경 없음 명시)

- INF-ORD-002 요청 파라미터(`memberId`) — 확정 문답 `scope_freeze`: "API 응답 계약은 바꾸지 않는다"에 따라 요청 스펙도 변경 대상 아님.
- INF-ORD-002 응답 필드 구성·타입·정렬·5건 고정 규칙 — 확정 문답 `scope_freeze`: recentOrders를 "그대로" 쓴다고 명시.
- INF-ORD-002 오류 응답 계약(404) — 확정 문답 `api_error`: 신규 오류 코드 없음.
- UIS-ORD-002(주문 상세) — 확정 문답 `scr_scope`: "기존 화면 중 바뀌는 것 없음", 이동 대상일 뿐 변경 없음.
- 타 도메인 테이블·집계(정산·통계류) — 확정 문답 `db_ripple`: "없음".
- 기존 데이터 이관·백필 — 확정 문답 `db_migration`: "불필요(신규 데이터만)".

## 회귀 범위

- 확정 문답 `regression_keep`: "기존 조회 결과 전부" — INF-ORD-002의 현재 응답(필드·값·정렬·5건 고정·취소 주문 포함 여부)이 이번 변경 전후 동일하게 유지되어야 한다.

## 롤백 요지

신규 화면(회원 상세/마이페이지, UIS 신규 채번)과 그 화면이 INF-ORD-002를 소비하도록 추가한 화면 연결(`screens` 갱신)을 제거하면 원상 복귀된다. INF-ORD-002 자체의 요청/응답/오류 계약은 이번 변경에서 손대지 않으므로 별도 API 롤백은 불필요하다.
