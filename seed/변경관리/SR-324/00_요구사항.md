# SR-324 — 쇼핑 SPA 회원가입 편입·로그인 필요 경로 가드

> 생성: 2026-09-19 · 출처: 로컬(SpecLens) · 계획 `_lab/plan/new_srs.json` N16 · 에픽 회원·인증 · 유형 화면 · Wave 1
> 벤치마크: KT알파쇼핑 — `_lab/plan/benchmark_ktalpha.md`(스크린샷 `_lab/plan/bench/`), 전체 계획 `_lab/plan/ECOMMERCE_PLAN.md`

## 요구 요지

Thymeleaf에 있는 회원가입을 쇼핑 SPA(/shop/signup)로 옮기고, 가입 완료 시 자동 로그인 후 원래 보던 페이지로 돌아간다. 장바구니·주문서·마이페이지는 비로그인 시 로그인으로 보내고 로그인 후 원래 경로로 복귀한다.

## 배경

가입만 서버 렌더 화면이라 쇼핑 → 가입 → 로그인 → 쇼핑 흐름이 끊긴다. 가입 API(INF-MBR-001·002)와 규칙은 SR-231 결정 그대로 쓴다.

## 범위

- 포함:
  - 3단계 가입 화면(인증코드 → 비밀번호·이름 → 약관·마케팅 동의, SR-231 UI/UX 그대로), 가입 완료 후 로그인 API 호출로 세션 저장, GNB·로그인 화면의 '회원가입' 링크, 보호 경로 가드(redirectTarget 재사용·오픈 리다이렉트 방지), 기존 Thymeleaf 가입 경로는 SPA로 안내(삭제하지 않음).
- 제외:
  - 소셜 로그인(SR-233), 약관 동의 이력 저장(후속), 가입 API 변경.

## 수용 기준

- [ ] 비로그인 사용자가 상품 상세에서 담기 → 로그인 화면 → 가입 → 완료 후 원래 상품 상세로 돌아온다
- [ ] 가입 API 계약·오류 코드(중복 이메일 '이미 가입된 이메일' + 로그인 링크 등)가 SR-231과 같다
- [ ] 보호 경로에 비로그인으로 들어가면 로그인으로 보내지고 외부 URL로의 복귀 요청은 무시된다
- [ ] 기존 Thymeleaf 가입 경로 접근 시 SPA 가입으로 이동하며 기존 가입 통합 테스트가 통과한다
