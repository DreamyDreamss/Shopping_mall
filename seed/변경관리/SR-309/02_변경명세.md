# SR-309 변경명세

## AS-IS → TO-BE 비교

### UIS-CMN-001 (디자인 토큰 — shop-web)

- AS-IS: 스펙 파일 없음(신규 산출물). `_impact.json`의 `new_specs`에 `UIS-CMN-001`(디자인 토큰, domain=common, module=shop-web)로만 등재돼 있고, 기존 UIS 화면설계서 대상은 없음(`affected.uis: []`). 요구사항 배경에 따르면 현재 shop-web은 화면마다 색·글자 크기·여백을 개별적으로 정의하고 있으며 공유 디자인 토큰이 없음.
- TO-BE: shop-web 전역 디자인 토큰을 CSS 변수 한 파일로 신설한다. 요구사항·확정 문답 근거로 다음을 담는다 —
  - 색 토큰: 본문 #101010, 보조 #767676 / #AAAAAA, 면 #F2F2F2 / #F5F5F5 / #F9F9F9, 포인트 보라 #713FC5(배경 #F2EBFF), 링크 파랑 #177BC3, 할인·가격 빨강 #FF5259, 브랜드 레드 #ED1C24, 딤 rgba(16,16,16,.3), 상태색(성공/경고/오류/정보)
  - 그라데이션 토큰 2종: 파랑→보라(구매 버튼·헤더 토글), 보라→파랑(최근 본 상품 헤더)
  - 타이포: Pretendard, 본문 14px 기준 스케일 8단, 굵기 3종, 배너 카피용 굵은 헤드라인 40px대
  - 간격: 4px 배수
  - radius: 3종(카드 썸네일 8px 포함)
  - 그림자: 3종
  - z-index 층
  - 레이아웃 폭: 본문 750px 단일 컬럼
  - Pretendard woff2 서브셋 저장소 번들(OFL 라이선스), `font-display: swap`, 시스템 한글 폰트 폴백(웹폰트 로드 실패 시 대체)
  - 로드 위치: 외부 CDN 없이 앱이 서빙하는 정적 경로(index.html/전역 CSS)
  - 스토리북 'Design Tokens' 문서 페이지 1개: 색 견본(토큰명·값·용도), 배경×본문 명도 대비 표(4.5:1 미달 조합 표시), 타이포 스케일 견본, 간격/radius/그림자 견본
  - 전역 body 폰트를 Pretendard로 교체(허용된 유일한 기존 스타일 변경)

## 제외(변경 없음 명시)

- 기존 화면·컴포넌트의 스타일 교체 — SR-310(공통 컴포넌트) · SR-311(앱 셸) · SR-322/326(리스킨)에서 다룸. 이번 SR은 토큰 신설만 하고 적용하지 않음.
- 다크 모드 — 범위 제외(확정 문답 scope_freeze).
- 백엔드(shop-api) 변경 — 없음(확정 문답 scope_freeze, db_ripple, db_migration).
- 타 도메인 테이블·집계(정산·통계류) — 파급 없음(확정 문답 db_ripple: "화면 스타일 토큰 SR이라 DB·테이블 변경이 없다").
- 데이터 이관·백필 — 대상 없음(확정 문답 db_migration).
- UIS 화면설계서 대상 화면 — 없음(확정 문답 scr_scope: "화면 내용 변경 없음 — 전역 토큰 파일·폰트 로드와 스토리북 Tokens 문서 페이지만 추가").
- 빈 값·오류 상태 화면 표기 — 해당 없음(확정 문답 scr_empty_state, SR-310으로 이연).
- 사용자 진입점 — 해당 없음(확정 문답 scr_entry: "개발자용 스토리북 문서 페이지뿐").

## 회귀 범위

- 기존 화면의 동작·문구·레이아웃 전부 불변(확정 문답 regression_keep).
- 기존 테스트(shop-web jest, 스토리북 빌드) 전부 통과 유지(확정 문답 regression_keep, 수용 기준 "기존 화면의 동작과 테스트가 그대로 통과한다").
- 토큰은 새로 추가만 하며 기존 스타일은 이 SR에서 바꾸지 않는다 — 유일한 예외는 전역 body 폰트의 Pretendard 교체이며, 이 교체로 레이아웃 붕괴가 없어야 한다(확정 문답 regression_keep).
- 새로 작성하는 스타일 코드는 하드코딩 색·px 대신 토큰을 참조해야 한다(요구사항 수용 기준 — 신규 파일 하드코딩 색 0건 검사).

## 롤백 요지

이 SR의 변경은 shop-web에 신규 파일(토큰 CSS 변수 파일, Pretendard woff2 서브셋 번들, 스토리북 'Design Tokens' 문서 페이지)을 추가하고 전역 body 폰트 선언 한 곳만 교체하는 형태다. 롤백은 역순으로: (1) 전역 body 폰트 선언을 토큰 도입 이전 값으로 되돌리고, (2) index.html/전역 CSS의 폰트 로드(`font-display: swap` 포함) 참조를 제거하고, (3) 스토리북 'Design Tokens' 문서 페이지를 삭제하고, (4) 토큰 CSS 변수 파일과 Pretendard woff2 서브셋 번들을 삭제한다. 기존 화면·컴포넌트는 이번 SR에서 토큰을 참조하도록 바뀌지 않으므로(SR-310/311/322/326에서 별도 진행) 롤백 시 기존 화면에 미치는 영향은 없다. DB·백엔드 변경이 없으므로 DB 롤백 절차는 불필요하다.
