# SR-315 — 상품 목록 조회 API 서버화 — 카테고리·브랜드·가격 필터·서버 정렬·페이지

> 생성: 2026-09-19 · 출처: 로컬(SpecLens) · 계획 `_lab/plan/new_srs.json` N07 · 에픽 전시 · 유형 API · Wave 1
> 벤치마크: KT알파쇼핑 — `_lab/plan/benchmark_ktalpha.md`(스크린샷 `_lab/plan/bench/`), 전체 계획 `_lab/plan/ECOMMERCE_PLAN.md`

## 요구 요지

GET /api/products에 카테고리(하위 포함)·브랜드(복수)·가격 범위·품절 제외 필터, 서버 정렬(추천·신상품·낮은가격·높은가격·판매량), 페이지(page·size·totalCount)를 추가한다. 키워드는 상품명·브랜드명·카테고리명까지 매칭한다.

## 배경

SR-303은 API 계약을 바꾸지 않으려고 정렬·페이지를 화면에서 처리했다(상품 4개일 때만 성립). 상품 60종·카테고리 탐색·검색에서는 서버 처리가 필요하다. SR-238(카테고리 목록 UI)·SR-240(검색 결과)의 공통 선행으로 SR-238의 API 부분을 분리한다.

## 범위

- 포함:
  - 파라미터 categoryId·brandIds·minPrice·maxPrice·inStock·keyword·sort·page·size(추가만, 없으면 기존 동작), 응답에 totalCount·page·facet(브랜드별·가격대별 개수) 추가, 판매량 정렬은 order_items 합계(취소 제외), 기존 화면(SR-303)을 서버 정렬·페이지로 전환.
- 제외:
  - 커서 기반 무한 스크롤(SR-238·291), 평점·배송 필터(리뷰·배송 정책 이후), 오타 교정(SR-239 잔여).

## 수용 기준

- [ ] 파라미터 없이 호출하면 기존 응답과 같은 항목이 같은 순서로 온다(하위호환)
- [ ] 대분류 categoryId로 조회하면 그 하위 중·소분류 상품이 모두 포함된다
- [ ] sort 값 5종이 서버에서 적용되고 같은 조건 재조회 시 순서가 안정적이다(동률은 sku 순)
- [ ] 잘못된 파라미터(음수 가격·역전된 범위·없는 sort)는 기존 오류 봉투로 400을 반환한다
- [ ] 상품 목록 화면이 서버 페이지로 동작하고 SR-303 상태(로딩·결과 없음·실패·마지막 페이지)가 유지된다
