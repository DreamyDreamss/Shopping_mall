# SR-203 요구사항

## 개요
- **SR 제목**: 체크아웃 — 장바구니를 주문으로 전환
- **요청자**: 운영기획팀 김보라
- **우선순위**: High
- **목표 일정**: 2026-10-02

## 변경 배경 및 목적
장바구니(SR-202)까지 열리면서 담기→확인 흐름은 생겼지만, 담은 것을 실제 **주문으로 전환**하는
길이 없다(현재 주문 생성은 API로 품목을 직접 넘기는 방식뿐). 장바구니에서 버튼 한 번으로
주문이 만들어지는 체크아웃을 도입해 "고객처럼 담고 주문까지" 흐름을 완결한다. 쇼핑몰 확장 3단계.

## 요구사항 상세

### 기능 요구사항
- **장바구니 화면에 [주문하기] 버튼 신설**: 그 회원의 장바구니 전체 품목을 한 번에 주문으로
  전환한다(부분 선택 주문은 이번 범위 밖).
- **전환 규칙**:
  - 주문 생성은 기존 주문 규칙을 그대로 따른다(주문번호 채번·상태 PLACED·재고 차감 등 —
    기존 주문과 동일해야 한다. 새 규칙을 만들지 말 것).
  - 전환에 성공하면 그 회원의 장바구니는 **비워진다**.
  - 전환 결과로 생성된 주문의 상세 화면(또는 주문번호 안내)으로 이동한다.
- **실패 처리**:
  - 품목 중 하나라도 재고가 부족하면 **주문 전체가 생성되지 않아야** 하고(부분 주문 금지),
    장바구니는 그대로 남아야 한다. 어떤 품목이 문제인지 사유를 보여준다.
  - 빈 장바구니에서는 주문하기가 동작하지 않는다(버튼 비활성 또는 안내).
- 담기 시점과 주문 시점 사이에 재고가 줄어 있을 수 있다(SR-202에서 예고) — 주문 시점의
  재고가 기준이다.

### 비기능 요구사항
- 전환은 원자적이어야 한다: 주문 생성·재고 차감·장바구니 비우기가 전부 되거나 전부 안 되거나.
- 이번 범위 밖: 결제, 배송지 입력(현 주문 생성 규칙에 없는 것은 추가하지 않는다), 부분 선택.

## AS-IS 현황
- 주문 생성: POST /api/orders (품목 배열 직접 전달) — 재고 차감 포함으로 알고 있음.
- 장바구니: 조회/담기/수량변경/삭제만 가능. 주문 전환 경로 없음.

## TO-BE 목표
- 장바구니 화면 [주문하기] → 주문 생성 + 재고 차감 + 장바구니 비움 → 주문 상세 확인.
- 재고 부족 시 전량 거부 + 사유 표시, 장바구니 보존.

## 영향 예상 범위 (선택)
- 화면: 장바구니 화면 수정(버튼) — 필요 시 주문 완료 안내
- API: 체크아웃 신규 1건(또는 화면 전환 처리 — 개발팀 설계). 기존 주문 생성 API는 무변경 유지
- DB: 테이블 변경 없음(기존 ORDERS/ORDER_ITEMS/CART_ITEMS 사용)
