# SR-203 분석서

## SR 개요
- **SR**: SR-203 — 체크아웃(장바구니→주문 전환) / **유형**: COMPOSITE(API_NEW + SCREEN_MODIFY)
- **우선순위**: High / **영향 도메인**: order / **분석일**: 2026-08-23 / **인입**: 로컬

## 요구사항 요약
장바구니 전체를 버튼 한 번으로 주문으로 전환. 기존 주문 규칙(채번·PLACED·재고 차감) 재사용,
성공 시 장바구니 비움+주문 상세 이동, 재고 부족은 **전량 거부**(부분 주문 금지)+장바구니 보존.
전환은 원자적(전부 되거나 전부 안 되거나).

## AS-IS 실측 (CIA + 소스)
- POST /api/orders(INF-ORD-005): OrderService가 주문번호 채번·PLACED·**decreaseStock**(재고
  부족 시 실패) 수행 — 체크아웃이 재사용할 정본 로직.
- 장바구니(SR-202): CART_ITEMS·CartService — 전환 경로 없음. UIS-ORD-005에 버튼 없음.
- 주문 상세 화면(/order/{orderNo}) 기존 존재 — 전환 후 착지 화면으로 재사용.

## 영향범위
| 구분 | AS-IS | 변경 유형 | 영향도 |
|------|-------|---------|--------|
| INF-ORD-014 (예약) | 없음 | 신규 — POST /api/cart/checkout (D6) | 중 |
| UIS-ORD-005 | 주문하기 없음 | [주문하기] 폼 추가 (SCREEN_MODIFY) | 하 |

**FUNC 구성(D7)**: 체크아웃 전체(API+화면 버튼·폼)는 **FUNC-order-012 단일 구현 단위**
(INF-ORD-014를 --new-inf로 예약 — 예약 FUNC). UIS-ORD-005의 FUNC(011)는 코드 구현이 없으므로
aidd에서 [건너뛰기] — 문서 갱신은 종결 단계 재생성이 담당. 스펙 파일을 찾지 말 것(7-N).

**회귀(ripple)**: 주문 생성 경로(INF-ORD-005 — 동일 서비스 공유), 재고 차감(PRODUCTS),
장바구니 CRUD(CART_ITEMS — checkout의 삭제와 공존), 주문 조회(INF-ORD-003/004 — 생성 주문
표시). 특히 **기존 POST /api/orders 무변경**이 1급 회귀 기준.

**제외**: 기존 INF 13종 전부·SCH 전부·타 화면.

## 변경 요구사항 (SR 단일축)
- REST: POST /api/cart/checkout {memberId} → 200 {orderNo,totalAmount,itemCount} /
  400(빈)·404(회원)·409(재고 부족 품목별 사유·전량 거부). 원자 트랜잭션.
- 화면: [주문하기] 폼(PRG) — 성공 redirect /order/{orderNo}, 실패 /cart+flash 사유,
  빈 장바구니 버튼 미노출. 전환 성공 시 장바구니 비워짐.
