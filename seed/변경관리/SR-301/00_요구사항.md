# SR-301 — 쇼핑 화면을 앱이 직접 서빙(단일 기동) — 재기동 한 번으로 화면 반영

> 생성: 2026-09-16 · 출처: 로컬(SpecLens)

## 요구 요지

## 요구 요지

React 쇼핑 화면(shop-web)이 별도 개발 서버(:5273)로만 떠서, 화면을 고쳐도 앱(shop-api :8087)을 재기동하는 것과 무관하다. shop-web 빌드 산출물을 shop-api가 `/shop/**` 경로로 직접 서빙해 **앱 재기동 한 번으로 화면 변경이 반영**되게 한다. SPA라 새로고침·딥링크에서도 `index.html`로 폴백해야 한다.

## 범위

- 대상 화면/API/테이블(짐작 가능한 만큼): shop-api 정적 리소스 매핑(`/shop/**`), SPA fallback 컨트롤러, shop-web 빌드 산출물(`dist`)을 두는 위치(빌드 시 복사 또는 기동 시 참조)
- 개발 서버(:5273)는 그대로 둔다(개발 중에는 계속 쓴다)

## 제약·유의

- 기존 `/api/**` 응답·인증(X-Api-Key)·기존 Thymeleaf 화면(`/orders` 등) 동작 불변
- `/shop` 하위가 아닌 경로는 지금 동작 그대로여야 한다(라우팅 가로채기 금지)
- 정적 자원 캐시 헤더로 배포 직후 옛 화면이 남지 않게 한다
