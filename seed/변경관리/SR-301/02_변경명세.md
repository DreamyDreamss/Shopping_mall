# SR-301 변경명세

## AS-IS → TO-BE 비교

### INF-ORD-017 (쇼핑 SPA 정적 서빙(/shop))

- AS-IS: 전용 스펙 파일 없음. `docs/변경관리/SR-301/_impact.json`은 이 ID를 `new_specs`(신규 배정)로 표시한다. 다만 저장소 조회 결과, 동일 ID `INF-ORD-017`이 `docs/00_FUNC/stories/STORY-FUNC-order-016.md`(SR-212, status: Approved, created: 2026-09-08, approved_sha: bb709b28d4bd)에서 이미 "상품 리뷰 등록/목록 API"(리뷰 테이블 `product_reviews`, 별점 1~5, 오류코드 ORD-4004/ORD-4090/ORD-4041 등) 용도로 예약되어 있다. 해당 스토리는 코드·스펙 본문이 아직 역생성되지 않은 상태(module에 리뷰 관련 컨트롤러 없음 확인)다. **[미상] 동일 ID가 서로 다른 두 SR(SR-212 리뷰 기능 vs SR-301 정적 서빙)에 배정된 충돌로 보이며, 이 SR 범위에서는 어느 배정이 유효한지 판정할 근거가 없다 — 승인권자 확인 필요.** 이하 TO-BE는 SR-301 요구사항·확정 문답만을 근거로 기술하며, ID 충돌 해소(재배정 등)는 이 문서의 범위 밖이다.
- TO-BE(요구사항·확정 문답 근거):
  - shop-api가 shop-web 빌드 산출물을 `/shop/**` 경로로 정적 리소스 매핑해 서빙한다.
  - `/shop` 하위에서 실제 정적 파일과 매칭되지 않는 경로는 SPA 폴백으로 `index.html`을 200으로 응답한다(신규고침·딥링크 대응).
  - 빌드 산출물(`dist`)을 두는 위치와 갱신 방법: 빌드 시 복사 또는 기동 시 참조 — 구체 방식은 요구사항에 확정되어 있지 않음 **[미상]**(확정 문답 1에서 "위치와 갱신 방법을 정한다"까지만 범위로 명시, 방식 자체는 명세 대상이나 확정 값 없음).
  - 캐시 헤더: 해시가 붙은 정적 자원(JS/CSS 등)은 장기 캐시, `index.html`은 no-cache.
  - 빌드 산출물이 없는 경우: 기동은 성공하되 `/shop` 접근 시 404 응답 + 서버 로그에 "shop-web 빌드 산출물 없음" 안내. 새 오류 코드는 만들지 않는다.
  - 사용자 대상 빈 상태 화면은 이 SR 범위 밖(서버 로그 안내로 대체).
  - 스토리북 스토리 산출물: 해당 없음(React 부품 신규 개발이 아님).

## 제외(변경 없음 명시)

- 쇼핑 화면 자체의 신규 개발 — 별도 SR로 분리(확정 문답 1)
- 개발 서버(:5273) 구성 변경 — 대상 아님, 개발 중 계속 사용(확정 문답 1, 요구사항 범위)
- 배포 자동화 — 대상 아님(확정 문답 1)
- `/api/**` 요청·응답 형식·인증(X-Api-Key)·오류 계약 — 변경 없음(확정 문답 2, 3)
- 기존 Thymeleaf 화면(`/orders`, `/order/list` 등) 경로·렌더링 — 변경 없음(확정 문답 2)
- `/shop` 밖 경로의 기존 라우팅 동작 — 변경 없음, 가로채기 금지(요구사항 제약, 확정 문답 2)
- 기존 정적 자원(있다면) 서빙 — 변경 없음(확정 문답 2)
- 화면 목록 — 이 SR로 신규/변경되는 화면 없음(확정 문답 5)

## 회귀 범위

- 기존 Thymeleaf 화면(`/orders`, `/order/list` 등) 경로와 렌더링 불변

(확정 문답 "반드시 유지돼야 하는 기존 동작(회귀 범위)은 무엇인가?" 답변 그대로 인용)

## 롤백 요지

`/shop/**` 정적 리소스 매핑과 SPA 폴백 컨트롤러(신규 추가분)를 제거하고, 빌드 산출물 복사/참조 설정을 되돌리면 이전 상태(shop-web은 개발 서버 :5273에서만 서비스)로 복귀한다. `/api/**`·기존 Thymeleaf 화면·인증·오류 계약은 이 SR에서 변경되지 않으므로 롤백 시 별도 조치가 필요 없다. 새 오류 코드가 없으므로 코드 계약 롤백도 불필요하다.
