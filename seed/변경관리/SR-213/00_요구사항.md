# SR-213 — 주문 목록 수령인 연락처 마스킹

> 생성: 2026-09-08 · 출처: 로컬(SpecLens)

## 요구 요지

주문 목록·상세에 수령인 휴대폰이 전체 노출된다. 화면과 API 응답 모두 마스킹한다.

- 표시 형식: 가운데 자리를 가린다(010-****-1234)
- 관리자 키(lab-admin-key)로도 목록에서는 마스킹한다(상세에서만 전체 노출)
- CSV 내보내기에도 같은 규칙을 적용한다

- **Q. 이번 SR에서 하는 것과 명시적으로 빼는 것은 무엇인가?**
  - A. 포함: 주문 목록 화면·목록 API 응답·CSV 내보내기의 수령인 휴대폰 마스킹. 제외: 주문 상세(권한 있는 사용자는 전체 노출), 회원 정보 화면, 수령인 이름·주소. (viewer · 2026-09-09 00:06)
<!-- clarify:regression_keep -->
- **Q. 반드시 유지돼야 하는 기존 동작(회귀 범위)은 무엇인가?**
  - A. 주문 목록의 건수·정렬·필터·페이징은 그대로다. 마스킹은 **표시 값만** 바꾸고 검색·정렬 기준은 원본을 쓴다(마스킹된 값으로 검색되면 안 된다). (viewer · 2026-09-09 00:06)
<!-- clarify:api_compat -->
- **Q. 기존 클라이언트와의 하위호환이 필요한가?**
  - A. 필드 추가만 — 기존 필드명·타입은 그대로 두고 값만 마스킹한다. 필드를 지우거나 이름을 바꾸면 기존 클라이언트가 깨진다. (viewer · 2026-09-09 00:06)
<!-- clarify:api_error -->
- **Q. 오류 응답 계약(코드·메시지)은 무엇인가?**
  - A. 이 SR은 오류 계약을 바꾸지 않는다. 마스킹 실패(형식 불명 번호 등)는 오류가 아니라 **전체 마스킹**으로 처리한다 — 가리는 데 실패했을 때 원본을 내보내면 안 된다. (viewer · 2026-09-09 00:06)

- **Q. 기존 데이터 이관·백필이 필요한가?**
  - A. 불필요(신규 데이터만) — 저장은 원본을 유지하고 조회 시점에 가린다. (viewer · 2026-09-09 00:06)
<!-- clarify:pii_surfaces -->
- **Q. 가려야 할 표면이 전부 나열됐는가? (화면·API 응답·내보내기·로그)**
  - A. 화면 + API + 내보내기/로그(전부). 주문 목록 화면, 목록 API 응답, CSV 내보내기 세 곳 모두. 서버 로그에 전화번호를 남기지 않는다. (viewer · 2026-09-09 00:06)
<!-- clarify:pii_role -->
- **Q. 권한별로 노출 범위가 다른가? (관리자·본인·타인)**
  - A. 권한별로 다름 — 목록은 관리자 키를 포함해 **모두 마스킹**한다(대량 열람 표면이라 유출 시 피해가 크다). 주문 상세는 관리자 키에 한해 전체 노출한다. (viewer · 2026-09-09 00:06)
<!-- clarify:pii_format -->
- **Q. 가리는 형식과 원본 보존 방침은?**
  - A. 가운데 자리를 별표로 가린다(010-****-1234). 앞 3자리·뒤 4자리는 남긴다 — 고객 응대 시 본인 확인에 쓰인다. 저장은 원본 유지, 조회 시점 변환이라 되돌릴 수 있다. 형식이 다른 번호(02-…, 국제번호)는 뒤 4자리만 남기고 나머지를 가린다. (viewer · 2026-09-09 00:06)
<!-- clarify:scr_scope -->
- **Q. 변경 대상 화면이 전부 나열됐는가? (누락 화면 없음 확인)**
  - A. 주문 목록(UIS-ORD-001) 한 화면. 주문 상세는 이번 범위가 아니다(전체 노출 유지). (viewer · 2026-09-09 00:06)
<!-- clarify:scr_empty_state -->
- **Q. 빈 값·오류 상태의 화면 표기는 무엇인가?**
  - A. 휴대폰이 비어 있으면 마스킹 대신 '-'를 표시한다(별표만 있는 칸은 번호가 있는 것처럼 보인다). (viewer · 2026-09-09 00:06)
