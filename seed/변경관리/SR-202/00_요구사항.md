# SR-202 요구사항

## 개요
- **SR 제목**: 장바구니 도입 (담기·조회·수량변경·삭제)
- **요청자**: 운영기획팀 김보라
- **우선순위**: High
- **목표 일정**: 2026-09-19

## 변경 배경 및 목적
상품 카탈로그(SR-201)가 열리면서 운영자들이 "고객처럼 담아보고 주문까지 이어지는 흐름"을
검증할 수단을 요구한다. 현재 주문 생성 API는 품목을 한 번에 넘겨야 해서, 여러 상품을 골라
모아 두는 중간 단계(장바구니)가 없다. 쇼핑몰 확장 2단계로 장바구니를 도입한다.
(체크아웃 — 장바구니를 실제 주문으로 전환 — 은 다음 SR(SR-203)로 분리한다.)

## 요구사항 상세

### 기능 요구사항
- **장바구니 담기**: 상품 상세 화면에서 수량을 지정해 "장바구니 담기"를 누르면 장바구니에
  쌓인다. 같은 상품을 다시 담으면 수량이 합산된다.
- **장바구니 조회 화면 신설**: 담긴 품목 목록(상품명·단가·수량·품목합계)과 전체 합계 금액을
  보여준다. 비어 있으면 "장바구니가 비어 있습니다"와 상품 목록으로 가는 링크를 보여준다.
- **수량 변경/삭제**: 각 품목의 수량을 바꾸거나 품목을 삭제할 수 있다. 수량은 1 미만이 될 수
  없다(1 미만 입력 시 거부 또는 삭제 유도 — 개발팀 판단, 결정 기록 남길 것).
- **재고 초과 방지**: 담기·수량변경 시 현재 재고를 넘는 수량은 거부하고 사유를 보여준다.
- **품절 상품**: 품절(재고 0) 상품은 담기 버튼을 비활성화하거나 거부한다.
- **장바구니 데이터는 서버에 보관한다** (브라우저 저장 아님 — 운영자 여러 명이 각자 확인 필요).
  사용자 개념: 현 시스템에 로그인이 없으므로 **회원ID를 담기 시점에 선택/입력**하는 방식으로
  회원별 장바구니를 구분한다(기존 회원 데이터 활용 — 개발팀이 더 나은 방식을 알면 제안).

### 비기능 요구사항
- 담기/조회/변경/삭제 각 1초 이내(품목 50건 기준).
- 이번 단계 범위 밖: 결제, 주문 전환(SR-203), 비회원 장바구니, 만료 정책.

## AS-IS 현황
- 장바구니 개념이 시스템에 전혀 없음(테이블·API·화면 모두 없음 — 개발팀 확인 필요).
- 상품 상세 화면(SR-201)에는 조회만 있고 액션 버튼이 없음.

## TO-BE 목표
- 상세 화면에서 회원 선택+수량 지정 → 담기 → 장바구니 화면에서 품목·합계 확인, 수량 변경·삭제.
- 재고를 넘거나 품절인 담기는 명확한 사유와 함께 거부된다.

## 영향 예상 범위 (선택)
- 화면: 신규 1(장바구니 조회) + 기존 1 수정(상품 상세 — 담기 폼)
- API: 신규 (장바구니 담기/조회/수량변경/삭제 — 개발팀 설계)
- DB: **신규 테이블 필요할 것으로 예상** (장바구니 품목 보관 — 개발팀 설계, 기존 테이블 변경 없음)
