# SR-323 — 모의 발송함 — 인증코드·주문 알림을 아웃박스에 기록하고 개발용으로 열람

> 생성: 2026-09-19 · 출처: 로컬(SpecLens) · 계획 `_lab/plan/new_srs.json` N15 · 에픽 알림·고객센터 · 유형 화면+API+DB · Wave 1
> 벤치마크: KT알파쇼핑 — `_lab/plan/benchmark_ktalpha.md`(스크린샷 `_lab/plan/bench/`), 전체 계획 `_lab/plan/ECOMMERCE_PLAN.md`

## 요구 요지

SMS·이메일·알림톡 발송을 실제로 하지 않고 NOTIFICATION_OUTBOX 테이블에 기록하는 발송 어댑터를 만든다. 개발용 발송함 화면에서 받는 사람별로 최근 발송(인증코드 포함)을 볼 수 있다.

## 배경

가입·비밀번호 재설정 인증코드와 주문 완료 알림이 실제 채널 없이 로그·DB에만 흩어져 있어 사람이 가입 흐름을 끝까지 따라가기 어렵다. SR-285(알림센터)·SR-261·SR-249의 발송 경로도 같은 어댑터를 써야 한다.

## 범위

- 포함:
  - NotificationSender 인터페이스와 Outbox 구현(채널·수신자·템플릿 코드·본문·발송 시각), 기존 인증코드 발송 지점을 어댑터 경유로 교체, 개발용 발송함 화면(관리자 키 또는 lab 프로파일에서만 노출), 보존 7일.
- 제외:
  - 실제 SMS·이메일·알림톡 연동, 수신 설정(SR-285), 알림 목록(고객용 — SR-285).

## 수용 기준

- [ ] 회원가입·비밀번호 재설정 인증코드 요청 시 아웃박스에 1행이 기록되고 발송함에서 코드가 보인다
- [ ] 운영 프로파일에서는 발송함 화면·API가 404다
- [ ] 기존 인증코드 발송·검증·레이트리밋 테스트(SR-294·295·297·298)가 그대로 통과한다
- [ ] 발송 실패(아웃박스 쓰기 실패)가 가입·재설정 요청 트랜잭션을 깨지 않는다는 기존 계약이 유지된다
