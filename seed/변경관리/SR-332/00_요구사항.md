# SR-332 — 관리자 영역 분리 — 관리자 계정·로그인·/admin 셸

> 생성: 2026-09-19 · 출처: 로컬(SpecLens) · 계획 `_lab/plan/new_srs.json` N24 · 에픽 관리자 · 유형 화면+API+DB · Wave 2
> 벤치마크: KT알파쇼핑 — `_lab/plan/benchmark_ktalpha.md`(스크린샷 `_lab/plan/bench/`), 전체 계획 `_lab/plan/ECOMMERCE_PLAN.md`

## 요구 요지

관리 기능을 쇼핑 화면과 분리한다: ADMIN_USERS(역할 ADMIN/OPERATOR), 관리자 로그인, /admin 셸(좌측 메뉴·상단 바), 기존 주문 목록·상세(현재 SPA 루트 '/')를 /admin/orders로 옮긴다. 정적 관리자 API 키('*') 대신 관리자 세션으로 관리 API를 호출한다.

## 배경

관리 권한은 application.yml의 정적 키 하나뿐이고 주문 관리 화면이 SPA 루트에 있어 쇼핑 부팅 리다이렉트(SR-302 재작업)로 억지로 비켜 가고 있다. SR-279~284 관리자 SR의 공통 선행이다.

## 범위

- 포함:
  - ADMIN_USERS·관리자 로그인/로그아웃 API, 관리 API 권한 판정(관리자 세션 또는 기존 키 — 기존 키는 하위호환으로 유지), /admin 라우트·가드·셸, 주문 목록·상세 이관(기존 URL은 새 경로로 이동), 쇼핑 루트를 /shop 홈으로 정리.
- 제외:
  - 관리자 메뉴별 기능(SR-279~284), 관리자 2단계 인증, 개인정보 열람 로그(SR-282).

## 수용 기준

- [ ] 관리자 로그인 없이 /admin 하위 경로에 가면 관리자 로그인으로 보내진다
- [ ] 회원 세션으로 관리 API를 호출하면 403이다
- [ ] 기존 정적 관리자 키 기반 테스트(ApiKeyAuth 계열)가 통과한다
- [ ] 기존 주문 목록·상세 기능(필터·정렬·CSV·취소)이 /admin/orders에서 그대로 동작한다
- [ ] 쇼핑 SPA 진입 시 더 이상 주문 목록이 루트에 나타나지 않는다
