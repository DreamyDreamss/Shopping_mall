# SR-313 — 카탈로그 기반 스키마 — 카테고리 3단·브랜드·상품 이미지·상품정보고시

> 생성: 2026-09-19 · 출처: 로컬(SpecLens) · 계획 `_lab/plan/new_srs.json` N05 · 에픽 상품 · 유형 API+DB · Wave 1
> 벤치마크: KT알파쇼핑 — `_lab/plan/benchmark_ktalpha.md`(스크린샷 `_lab/plan/bench/`), 전체 계획 `_lab/plan/ECOMMERCE_PLAN.md`

## 요구 요지

실제 몰처럼 보이는 데 필요한 카탈로그 테이블을 만든다: 카테고리(3단 트리, 대분류 9개 — KT알파쇼핑 카테고리 서랍 기준), 브랜드, 상품 다중 미디어(대표·추가·상세 설명·영상), 상품정보제공고시, 연관 태그. products에 카테고리·브랜드·요약·원산지·등록일 컬럼을 더하고 조회 응답에 필드를 추가한다.

## 배경

지금 products에는 4개 상품과 sku·이름·가격·재고·정가·대표 이미지뿐이라 카테고리 탐색·브랜드·갤러리·고시 표를 만들 원천이 없다. 홈 카테고리 아이콘도 shopStatic.ts에 하드코딩돼 있다. SR-237·238·244·279가 모두 이 스키마를 전제로 한다.

## 범위

- 포함:
  - 신규 테이블 CATEGORIES(category_id, parent_id, depth 1~3, category_name, sort_order, icon_url, use_yn), BRANDS(brand_id, brand_name, logo_url, banner_url, use_yn), PRODUCT_IMAGES(sku, seq, media_kind MAIN/EXTRA/DETAIL/VIDEO, url), PRODUCT_NOTICES(sku, seq, item_name, item_value), PRODUCT_TAGS(sku, tag); PRODUCTS에 category_id(소분류)·brand_id·summary·origin·created_at 추가(NULL 허용); 기동 DDL은 다음 번호 V 파일에 IF NOT EXISTS(랩 규칙 ddl-idempotent) — 구조만, 상품 데이터는 넣지 않는다; GET /api/categories(트리+판매중 상품 수, 공개 GET); 상품 목록·단건 응답에 brand·categoryPath·images·notices·tags 추가(추가만). 대분류 9개 기준: 의류/언더웨어·패션슈즈/잡화·화장품/이미용·가전/디지털·스포츠/레저·식품/건강·주방/생활/애견·가구/인테리어·여행/문화.
- 제외:
  - 데이터 적재(카탈로그 적재 SR), 필터·정렬 API, 관리자 편집(SR-279), 옵션/단품, TV상품·무이자 속성.

## 수용 기준

- [ ] 빈 DB와 기존 DB 모두에서 기동 DDL이 오류 없이 두 번 연속 실행된다(멱등)
- [ ] GET /api/categories가 depth 1~3 트리와 각 노드의 판매중 상품 수(하위 포함)를 반환하고 인증 없이 조회된다
- [ ] 상품 단건 응답에 brand{id,name}·categoryPath[대,중,소]·images[]·notices[]가 추가되고 기존 필드·의미는 불변이다
- [ ] 기존 4개 상품과 장바구니·주문·체크아웃 흐름이 그대로 동작한다(sku 키·order_items 계약 불변)
- [ ] 새 테이블의 SCH 스펙과 API INF 스펙이 생성·갱신된다

- **Q. 반드시 유지돼야 하는 기존 동작(회귀 범위)은 무엇인가?**

- **Q. 이 SR이 바꾸는 테이블을 읽는 다른 API(INF-ORD-004, INF-ORD-005, INF-ORD-006, INF-ORD-010, INF-ORD-011, INF-ORD-012, INF-ORD-013)의 결과·오류 판정이 달라지는가?**
