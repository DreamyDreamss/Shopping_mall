# SR-313 변경명세

## AS-IS → TO-BE 비교

### INF-PRD-001 (카테고리 트리 조회 — 신규, SR-313.1)
- AS-IS: 없음 — 해당 스펙 파일 자체가 존재하지 않는다(신규 엔드포인트).
- TO-BE: `GET /api/categories` 신설. 인증: 무키 GET 공개(기존 `/api/products` 공개 판정과 같은 방식 — 확정 문답 api_compat). 응답: depth 1~3 카테고리 트리, 대분류 9개(의류/언더웨어·패션슈즈/잡화·화장품/이미용·가전/디지털·스포츠/레저·식품/건강·주방/생활/애견·가구/인테리어·여행/문화 — `_lab/catalog/catalog.json`의 categories와 같은 이름·순서), 각 노드에 판매중 상품 수(하위 포함) 포함. 오류 경로 없음 — 빈 트리면 빈 배열(확정 문답 api_error). 새 오류 코드 없음. 참조 테이블: CATEGORIES(신규), 상품 수 집계에 PRODUCTS(sale_yn='Y' 필터) 조인.

### INF-ORD-008 (GET /api/products — 판매중 상품 목록 조회, SR-313.2)
- AS-IS: 요청 파라미터 `keyword`(선택, 부분일치)·`inStock`(선택, 재고 필터). 응답 필드 7개: `sku`·`productName`·`price`·`stockQty`·`saleYn`·`listPrice`·`imageUrl`. 인증: 무키 GET 공개(SR-307), 키를 보낸 요청은 기존 인가 판정 그대로. 오류: 400(유효성 실패)·401(인증 실패). 참조 테이블: PRODUCTS([[SCH-ORD-005]])만.
- TO-BE: 요청 파라미터 `keyword`·`inStock` 불변(추가·변경 없음). 응답에 `brand`{id,name}·`categoryPath`[대,중,소]·`images`[]·`notices`[]·`tags`[] 5개 필드 추가(기존 7필드 이름·순서·타입 불변, 값이 없으면 `brand`는 null, 나머지는 빈 배열 — 확정 문답 regression_keep). 인증·오류(400/401) 계약 불변, 새 오류 코드 없음. 참조 테이블에 CATEGORIES·BRANDS·PRODUCT_IMAGES·PRODUCT_NOTICES·PRODUCT_TAGS 5개 신규 테이블 추가(PRODUCTS.category_id·brand_id를 통한 조회 대상).

### INF-ORD-009 (GET /api/products/{sku} — 상품 단건 조회, SR-313.3)
- AS-IS: 파라미터 `sku`(PathVariable, 필수). 응답 필드 7개(목록과 동일 구조). `sale_yn` 필터 없음(판매종료 상품도 SKU를 알면 조회 가능). 인증: 무키 GET 공개하되 `SKU-` 접두사 형식(`^/api/products/(SKU-[A-Za-z0-9-]+)$`)만 매치, 그 외 무키 401(fail-closed). 오류: 401(인증 실패, 형식 불일치 포함)·404(상품 없음). 참조 테이블: PRODUCTS만.
- TO-BE: 파라미터 `sku` 불변. 응답에 `brand`·`categoryPath`·`images`·`notices`·`tags` 5개 필드 추가(기존 7필드 불변, 값 없으면 null/빈 배열). `sale_yn` 무필터 동작 불변. 인증(`SKU-` 접두사 공개 판정) 불변. 오류(401/404) 계약 불변, 404 판정 기준(sku로 조회된 상품 없음) 불변, 새 오류 코드 없음. 참조 테이블에 신규 5개 테이블 추가.

### SCH-ORD-005 (products, SR-313.2/313.3 공통)
- AS-IS: 컬럼 7개 — `sku`(PK)·`product_name`·`price`·`stock_qty`·`sale_yn`·`list_price`·`image_url`. 인덱스 없음. FK/관찰조인: `sku` → ORDER_ITEMS.sku(쿼리관찰 2건). 상시 필터: `SALE_YN = 'Y'`. 참조 API 9개(INF-ORD-004·005·006·008·009·010·011·012·013).
- TO-BE: 컬럼 5개 추가(모두 NULL 허용) — `category_id`(소분류, CATEGORIES 참조)·`brand_id`(BRANDS 참조)·`summary`·`origin`·`created_at`. 기존 7컬럼의 이름·타입·NULL 여부·기본값·의미 불변(확정 문답 regression_keep). 기존 인덱스(없음)·기존 FK/관찰조인(`sku`→ORDER_ITEMS) 불변. 신규 FK(NULL 허용): `products.category_id` → CATEGORIES.category_id, `products.brand_id` → BRANDS.brand_id. 상시 필터 `SALE_YN='Y'` 불변. 기존 4행(SKU-1001~1004)은 신규 5컬럼이 NULL로 남는다(백필 없음 — 확정 문답 db_migration). DDL은 다음 번호 V 파일에 `CREATE TABLE IF NOT EXISTS`·`ALTER TABLE ADD COLUMN IF NOT EXISTS`로 멱등 추가(기존 V 파일 수정 없음).

## 제외(변경 없음 명시)
- INF-ORD-004, INF-ORD-005, INF-ORD-006, INF-ORD-010, INF-ORD-011, INF-ORD-012, INF-ORD-013 — PRODUCTS 기존 컬럼(`sku`·`product_name`·`price`·`stock_qty`·`sale_yn`·`list_price`·`image_url`)만 읽으므로 결과·오류 판정 불변(확정 문답 db_readers 근거, 이 API들의 기존 테스트가 그대로 통과하는 것으로 확인)
- 필터·정렬 API(카테고리·브랜드 기준 검색/정렬) — SR-315로 이관(요구사항 범위 '제외' 절)
- 관리자 편집(카테고리·브랜드·이미지·고시·태그 CRUD 화면/API) — SR-279로 이관
- 옵션/단품 — SR-342로 이관
- TV상품·무이자·청구할인 속성 — SR-318로 이관
- 카탈로그 실데이터 적재(카테고리 트리 값, 브랜드, 이미지, 고시, 태그의 실제 행) — SR-314로 이관. 이번 SR은 DDL(구조)만, 상품 데이터는 넣지 않는다
- 기존 V 마이그레이션 파일(V1~V9) — 수정 없음, 신규 변경은 다음 번호 V 파일로만 추가
- 기존 PRODUCTS 4행(SKU-1001~1004)의 `sku`·`product_name`·`price`·`stock_qty`·`sale_yn`·`list_price`·`image_url` 값 — 불변, 신규 5컬럼은 백필 없이 NULL로 남음
- ORDERS·ORDER_ITEMS·CART_ITEMS 및 정산·통계 집계 테이블 — sku로만 PRODUCTS를 참조하므로 이번 컬럼 추가의 영향 없음(확정 문답 db_ripple)

## 회귀 범위
- 기존 4개 상품(SKU-1001~1004)의 조회·장바구니·주문·체크아웃 흐름과 `sku` 키·`order_items` 계약 불변
- 기존 상품 목록·단건 응답(`GET /api/products`, `GET /api/products/{sku}`)의 기존 필드명·타입·의미 불변 — 새 필드는 추가만, 값이 없으면 null 또는 빈 배열
- 기존 V 마이그레이션 파일은 수정하지 않는다
- INF-ORD-004·005·006·010·011·012·013의 결과·오류 판정 불변 — 확인 방법: 이 API들의 기존 테스트가 그대로 통과해야 한다
- 기존 오류 응답 계약(code+message) 그대로, 새 오류 코드 없음

## 롤백 요지
`GET /api/categories`(INF-PRD-001, 신규 엔드포인트)를 제거하고, `GET /api/products`·`GET /api/products/{sku}` 응답에서 `brand`·`categoryPath`·`images`·`notices`·`tags` 5개 추가 필드를 걷어내 기존 7필드 계약으로 되돌린다. 이어서 `PRODUCTS.category_id`·`brand_id`·`summary`·`origin`·`created_at` 컬럼(신규, NULL 허용)과 CATEGORIES·BRANDS·PRODUCT_IMAGES·PRODUCT_NOTICES·PRODUCT_TAGS 5개 신규 테이블을 걷어낸다 — 모두 다음 번호 V 파일 하나에 담기므로 그 파일을 되돌리면 되고, 기존 V1~V9 파일은 손대지 않았으므로 별도 조치가 필요 없다. 기존 PRODUCTS 7컬럼·행 값과 `sku` FK(ORDER_ITEMS)는 이번 SR에서 변경하지 않았으므로 롤백 시 데이터 복구가 필요 없다.
