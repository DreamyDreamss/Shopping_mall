# SR-312 변경명세

## AS-IS → TO-BE 비교

### UIS-CMN-004 (신규 — 상품 카드 규격, 아직 스펙 파일 없음)
- AS-IS: 해당 스펙 없음(신규 UIS — 확정 문답 `scr_scope`가 "새 공통 UIS: UIS-CMN-004 상품 카드 규격"으로 명시).
- TO-BE: `ProductCard` v2 한 컴포넌트, 변형 3종(`grid`·`rail`·`ranking`). 요소:
  - 정사각 썸네일(라운드 8px), 이미지 없음/로드 실패 시 회색 대체 영역(상품명 첫 글자 없는 빈 틀 — 기존 이니셜 대체와 다름, 확정 문답 `scr_empty_state`)
  - 상품명 2줄 말줄임
  - 가격: 할인율(빨강, `floor((정가-판매가)/정가×100)`) + 판매가(굵게) + 정가(취소선). 정가 없거나 판매가 이상이면 할인 표기(할인율·취소선) 없음 — SR-306 계산 규칙 그대로 재사용, 모양만 새 컴포넌트로 이관.
  - 배지 줄: TV상품·무료 배송·무이자 N 중 값 있는 배지만 나열, 전부 없으면 줄 자체 숨김(빈 자리 남기지 않되 그리드 행 높이는 정렬)
  - 별점·상품평 수: 데이터 없으면 숨김(가짜 값 금지, SR-304 결정 유지)
  - 범위가('82,900원~'): 옵션 가격 폭이 있을 때만 표시
  - `ranking` 변형: 순위 배지 추가
  - 품절: 이미지 흐림 + '품절' 배지(SR-216·230 문구 유지, 모양만 배지화)
  - 이미지 lazy 로딩
  - SR-309 토큰, SR-310 `Badge` 컴포넌트 사용
- 제외(이 SR에서 만들지 않음): 배지·별점·리뷰수·범위가의 원천 데이터 배선(각 항목 아래 [제외] 절 참조)

### UIS-ORD-008 (shop — 쇼핑 홈)
- AS-IS(§2 화면구성): 추천 상품 영역이 `ProductGrid.tsx` + `ProductCard.tsx`(v1) 사용 — 카드 구성은 "썸네일(없으면 이니셜 대체), 상품명, 판매가, 정가 취소선, 할인율 배지, 품절 배지"뿐(§2 표). 배지 줄(TV상품/무료배송/무이자)·별점/상품평 수·범위가 요소 없음. 랭킹 영역(`RankingSection.tsx`)은 "탭으로 기준 전환, 순위 숫자와 상위 5개"로만 기술되고 카드 부품·구성 요소는 스펙에 명시돼 있지 않음(§2 표 — RankingSection 행에 `ProductCard` 재사용 여부 언급 없음).
- TO-BE:
  - 추천 상품(`ProductGrid.tsx`)의 카드가 `ProductCard` v2 `grid` 변형으로 교체 — 배지 줄·별점/상품평 수·범위가 요소 추가(값 있을 때만), 이미지 대체 영역이 이니셜 → 빈 회색 틀로 변경.
  - 랭킹 섹션(`RankingSection.tsx`) 카드에 순위 배지가 필요하다는 점은 요구사항 범위("순위 배지(ranking 변형)")로 확정돼 있으나, 이 변형을 랭킹 섹션이 소비한다는 화면별 매핑은 확정 문답에 명시적 문장으로 나오지 않음 — **[미상, 확인 필요]**: `RankingSection.tsx`가 `ProductCard` v2 `ranking` 변형으로 교체되는지, 아니면 `ranking` 변형이 다른 화면(예: 목록 화면 정렬 결과) 용도인지는 STORY 단계에서 화면 담당자 확인 필요.
  - §4 호출 API·§3 검증 규칙(정가·할인율 계산, 최근 본 상품 중복 제거 등)은 불변 — 값 계산 로직 변경 없음, 렌더링 컴포넌트만 교체.

### UIS-ORD-009 (shop_products — 상품 목록)
- AS-IS(§2 화면구성): 상품 그리드(`ProductListGrid.tsx`)가 "홈과 같은 `ProductCard` 재사용"(v1). 카드 구성 요소는 UIS-ORD-008과 동일 수준(배지 줄·별점·범위가 없음).
- TO-BE: `ProductListGrid.tsx`의 카드가 `ProductCard` v2 `grid` 변형으로 교체(홈과 동일 변형 공유). §3의 파생 순서(서버 응답 → 가격대 필터 → 정렬 → 페이지 slice)·결과 개수 텍스트 산정 시점·§5의 스켈레톤 표시 상태 로직은 카드 내부 구성과 무관하므로 불변.

### UIS-ORD-010 (shop_products_상세 — 관련 상품 레일만 해당)
- AS-IS(§2 화면구성): "함께 보면 좋은 상품" 블록(`RelatedProducts.tsx` + `relatedProductsPicker.ts`) — 스펙 §2 표에는 카드 부품명이 명시돼 있지 않음(`ProductCard` 재사용 여부 불명, `RelatedProducts.tsx` 자체 렌더 추정). §5 상태표에는 "함께 보면 좋은 상품 — 기본/비어있음" 두 상태만 정의.
- TO-BE: `RelatedProducts.tsx`의 카드가 `ProductCard` v2 `rail` 변형으로 교체(가로 스크롤 레일). 후보 산출 로직(`relatedProductsPicker.ts`, 현재 상품 제외 앞 8개, 후보 0개 시 섹션 자체 숨김)은 불변 — 카드 렌더만 교체.
- 이 UIS의 나머지 블록(이미지 갤러리·상품 정보 패널·상세 탭·상품정보제공고시, §2의 다른 행들)은 `ProductCard`를 쓰지 않으므로 이번 SR 대상이 아님(§6 "미확인 사항"의 품절 텍스트 표기 건도 `ProductInfoPanel`의 별도 미확정 이월 항목이며 이번 SR의 카드 배지와는 무관 — 제외 절 참조).

## 제외(변경 없음 명시)
- 배지 원천 데이터(TV상품/무이자 SR, 무료배송 SR-308/268) — 요구사항 범위에서 명시 제외, 카드는 값이 오면 표시하는 그릇만 만든다.
- 좋아요 동작(SR-243) — 요구사항 범위에서 명시 제외.
- 리뷰 데이터(SR-246) — 요구사항 범위에서 명시 제외, 카드의 별점/상품평 수는 데이터가 없으면 숨김.
- 나의 최대 혜택가(SR-345) — 요구사항 범위에서 명시 제외.
- 백엔드/서버 API 계약 — 요구사항 범위에서 명시 제외. `GET /api/products`(INF-ORD-008) 등 UIS-ORD-008/009/010이 호출하는 API 목록·파라미터·응답 계약은 불변(화면 컴포넌트 SR, DB 변경 없음 — 확정 문답 `db_ripple`·`db_migration`).
- UIS-ORD-010의 `ProductInfoPanel` 품절 표시(현재 텍스트 한 줄, §6 "미확인 사항"의 이월 항목) — `ProductCard`가 아니라 상세 페이지 정보 패널의 별도 표기이므로 이번 SR 범위 밖, 그대로 유지.
- UIS-ORD-008의 GNB·히어로 배너·카테고리 숏컷·최근 본 상품·푸터 — 카드 교체와 무관, 변경 없음.
- UIS-ORD-009의 필터바(`ProductFilterBar.tsx`)·페이지네이션(`ProductPagination.tsx`)·정렬/필터 클라이언트 계산 로직·`PAGE_SIZE=12` — 변경 없음.
- UIS-ORD-010의 담기/바로 구매 버튼 동작(`disabledReason` 판정, 연타 방지, API 파라미터)·상세 탭·상품정보제공고시 — 변경 없음.
- 목록/홈의 빈 결과·오류 상태 문구(EmptyState) — 확정 문답 `scr_empty_state`가 "각 화면 기존 문구 유지(EmptyState 교체는 리스킨 SR)"로 명시, 이번 SR 제외.

## 회귀 범위
- 홈·목록·상세의 상품 클릭 이동, 장바구니 담기, 검색·카테고리 필터, 정렬·페이지 동작과 기존 테스트가 불변이어야 한다.
- 가격·할인 계산 결과(SR-306)와 품절 문구(SR-216·230)는 불변 — 이번 SR은 모양(컴포넌트·마크업)만 바꾼다.

## 롤백 요지
`ProductCard` v2 도입 역순으로 되돌린다: UIS-ORD-008의 `ProductGrid`(및 [미상] 확인 결과에 따라 `RankingSection`)·UIS-ORD-009의 `ProductListGrid`·UIS-ORD-010의 `RelatedProducts`가 참조하는 카드 컴포넌트를 기존 `ProductCard`(v1)로 되돌리고 v2 컴포넌트·스토리를 제거한다. 신설 예정인 `UIS-CMN-004` 스펙 초안은 폐기한다. 가격 계산·품절 문구·API 계약은 이번 SR에서 애초에 손대지 않으므로 별도 되돌릴 것이 없다.
