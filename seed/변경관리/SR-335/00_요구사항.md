# SR-335 — 모의 택배사 어댑터 — 송장 발급·배송 이벤트 시뮬레이터

> 생성: 2026-09-19 · 출처: 로컬(SpecLens) · 계획 `_lab/plan/new_srs.json` N27 · 에픽 배송·반품 · 유형 API+DB · Wave 2
> 벤치마크: KT알파쇼핑 — `_lab/plan/benchmark_ktalpha.md`(스크린샷 `_lab/plan/bench/`), 전체 계획 `_lab/plan/ECOMMERCE_PLAN.md`

## 요구 요지

실 택배사 API 대신 CarrierClient 인터페이스와 모의 구현을 만든다. 송장을 등록하면 시간이 흐름에 따라(또는 관리자 버튼으로) 집하→이동→배달출발→배달완료 이벤트가 생긴다. SR-264(배송 추적)·SR-265(구매 확정)가 이 어댑터를 쓴다.

## 배경

SR-264는 택배사 API 연동을 전제로 하지만 랩에는 외부 연동이 없다. 연동 경계를 먼저 두면 SR-264는 추적 로직·화면에 집중할 수 있다.

## 범위

- 포함:
  - CarrierClient(송장 검증·상태 조회), 모의 구현(송장 번호 규칙, 이벤트 스크립트, 가속 모드), 택배사 코드표(3사), 관리자 '다음 단계로' 버튼.
- 제외:
  - 실 택배사 연동, 30분 주기 동기화 배치·고객 추적 화면(SR-264), 구매 확정 배치(SR-265).

## 수용 기준

- [ ] 형식이 틀린 송장 번호는 등록 시 거부된다
- [ ] 모의 송장 조회가 이벤트 순서(집하→이동→배달출발→배달완료)를 시간 순으로 돌려준다
- [ ] 가속 모드에서 배달완료까지 수 분 안에 도달한다
- [ ] 어댑터 구현을 교체해도 호출부 코드가 바뀌지 않는 인터페이스다
