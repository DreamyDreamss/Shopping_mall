# SR-322 — 기존 화면 리스킨 — 상품 목록·로그인·비밀번호 재설정·배송지 관리

> 생성: 2026-09-19 · 출처: 로컬(SpecLens) · 계획 `_lab/plan/new_srs.json` N14 · 에픽 UI/UX · 유형 화면 · Wave 1
> 벤치마크: KT알파쇼핑 — `_lab/plan/benchmark_ktalpha.md`(스크린샷 `_lab/plan/bench/`), 전체 계획 `_lab/plan/ECOMMERCE_PLAN.md`

## 요구 요지

이미 있는 화면 중 다른 SR이 다시 그리지 않는 것(상품 목록 SR-303, 로그인 SR-232, 비밀번호 재설정 SR-234, 마이페이지 배송지 관리 SR-235)을 디자인 토큰·공통 컴포넌트·앱 셸로 옮긴다. 동작·API 계약은 바꾸지 않는다.

## 배경

리스킨 대상 전체 지도: 홈=홈 섹션 데이터화 SR, 상품 상세=상세 레이아웃 SR, 장바구니·주문서=장바구니·주문서 리스킨 SR, 나머지 4화면=이 SR. 이 넷은 기능 위주로 만들어져 새 디자인 시스템과 따로 논다.

## 범위

- 포함:
  - 상품 목록(필터 바·정렬 칩·결과 수·카드 그리드 2열·페이지/더보기), 인증 화면 공통 틀(로고·단일 컬럼·하단 보조 링크)로 로그인·재설정, 배송지 목록·폼·우편번호 모달(BottomSheet), 입력 오류 표기 통일.
- 제외:
  - 회원가입(SPA 편입 SR에서 새로 만든다), 주문 목록/상세(관리자 화면 — 관리자 분리 SR), 기능 변경.

## 수용 기준

- [ ] 네 화면이 하드코딩 스타일 없이 디자인 토큰·공통 컴포넌트만으로 그려지고 앱 셸 안에 들어간다
- [ ] 기존 단위·통합 테스트와 스토리(잠금 안내·코드 재발송·배송지 0/10건·목록 결과 없음 등)가 모두 통과한다
- [ ] 입력 오류가 해당 필드 아래에 표시되고 aria-describedby로 연결된다
- [ ] 요청·응답·오류 코드 계약 변경이 없다

## 선행 SR

- SR-310, SR-311, SR-312, SR-235

## 제약·유의

- (SR-311 QA 이월, 2026-09-19) 1200~1237px 폭에서 AppShell 우측 레일이 뷰포트 밖으로 최대 19px 넘쳐 가로 스크롤이 생긴다(minmax(0,1fr) 절충) — 레일 폭 축소 또는 1240px 미만에서 레일 숨김으로 해소.

- (SR-309 QA 이월, 2026-09-19) 기존 쇼핑 화면·부품 루트의 인라인 `fontFamily:'system-ui, sans-serif'`(프로덕션 10개 페이지·15개 파일)가 전역 body Pretendard를 가린다 — 리스킨 때 인라인 폰트 지정을 제거하고 토큰을 따르게 한다(브라우저에서 document.fonts의 Pretendard가 loaded인지 확인).

- KT알파쇼핑 상품 이미지·디자인 자료는 사내 로컬 테스트베드 한정(외부 배포·공개 저장소 반입 금지) — 이미지는 모듈 git에 넣지 않는다.
- 기존 종결 SR의 확정 결정을 뒤집을 때는 확정 문답에 사유를 남긴다.
