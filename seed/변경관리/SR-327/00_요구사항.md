# SR-327 — 모의 결제(Mock PG) 어댑터·테스트 결제창

> 생성: 2026-09-19 · 출처: 로컬(SpecLens) · 계획 `_lab/plan/new_srs.json` N19 · 에픽 주문·결제 · 유형 화면+API+DB · Wave 1
> 벤치마크: KT알파쇼핑 — `_lab/plan/benchmark_ktalpha.md`(스크린샷 `_lab/plan/bench/`), 전체 계획 `_lab/plan/ECOMMERCE_PLAN.md`

## 요구 요지

실제 PG 없이 결제 흐름을 끝까지 돌리는 모의 PG를 만든다: PaymentGateway 인터페이스 + MockPg 구현, PAYMENTS 테이블, 주문서 [결제하기] → '테스트 결제' 표시가 붙은 결제창(카드·계좌이체·간편결제 선택, 승인/실패/사용자 취소 버튼) → 승인 시 결제대기→결제완료.

## 배경

SR-305는 '가짜 결제 화면을 만들지 않는다'로 checkout 호출까지만 했다. 이 SR은 그 결정을 명시적으로 넘어선다 — 실 PG 대신 샌드박스 역할의 모의 결제창을 두되, 화면에 '테스트 결제'를 분명히 표시해 실결제로 오인되지 않게 한다. SR-256(실 PG 연동)은 이 인터페이스 위의 결제수단 확장으로 범위를 바꾼다.

## 범위

- 포함:
  - PAYMENTS(payment_id, order_no, method, amount, status READY/APPROVED/FAILED/CANCELED, pg_tid, approved_at, fail_reason), 결제 준비·승인·실패 API(금액은 서버 재계산값과 대조), 모의 결제창 화면, 주문 완료 화면 연결, 결제 실패 시 주문서로 돌아가 입력 유지, 결제 정보(카드번호 등) 미저장.
- 제외:
  - 실 PG·결제 키, 가상계좌 입금 시뮬레이션·웹훅(SR-260), 부분 취소(SR-262), 할부 표시(SR-256 잔여).

## 수용 기준

- [ ] 승인 버튼으로 결제하면 PAYMENTS APPROVED 1행·주문 PAID 전이·상태 이력 1행이 생기고 주문 완료 화면으로 간다
- [ ] 실패·사용자 취소 시 주문은 결제대기로 남고 사유가 기록되며 주문서 입력이 유지된다
- [ ] 클라이언트가 보낸 금액이 서버 재계산 금액과 다르면 승인이 거부된다
- [ ] 같은 결제 요청을 두 번 보내도 승인은 한 번만 일어난다(멱등)
- [ ] 결제창과 결제 결과 화면에 '테스트 결제' 표시가 있다
