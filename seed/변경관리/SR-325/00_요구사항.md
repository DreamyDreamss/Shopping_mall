# SR-325 — 주문 상태 모델 정비 — 결제대기~구매확정 상태·상태 이력

> 생성: 2026-09-19 · 출처: 로컬(SpecLens) · 계획 `_lab/plan/new_srs.json` N17 · 에픽 주문·결제 · 유형 API+DB · Wave 1
> 벤치마크: KT알파쇼핑 — `_lab/plan/benchmark_ktalpha.md`(스크린샷 `_lab/plan/bench/`), 전체 계획 `_lab/plan/ECOMMERCE_PLAN.md`

## 요구 요지

주문 상태를 커머스 표준 흐름으로 넓힌다: 결제대기(PAYMENT_PENDING)·결제완료(PAID)·상품준비중(PREPARING)·배송중(SHIPPED)·부분배송(PARTIAL_SHIPPED)·배송완료(DELIVERED)·구매확정(CONFIRMED)·취소(CANCELED). 허용 전이표를 코드 한 곳에 두고 ORDER_STATE_HISTORY에 전이를 기록한다.

## 배경

orders.order_state는 PLACED/PAID/SHIPPED/PARTIAL_SHIPPED/CANCELED/DONE뿐이라 결제 대기·배송 완료·구매 확정을 구분할 수 없다. 모의 결제(N19)·배송 추적(SR-264)·구매 확정(SR-265)·리뷰(SR-246)·반품(SR-266)이 모두 이 상태를 전제로 한다.

## 범위

- 포함:
  - 상태 코드 추가와 기존 값 매핑(PLACED는 결제 연동 전 주문을 뜻하므로 유지하되 신규 주문은 PAYMENT_PENDING, DONE→CONFIRMED 표시 매핑은 결정 후 기록), 전이표 단일 지점(허용되지 않은 전이는 409), ORDER_STATE_HISTORY(order_no, from_state, to_state, reason, actor, changed_at), 상태 라벨 한글화(SR-222 규칙 확장), 주문 목록 상태 필터 값 추가.
- 제외:
  - 결제(N19), 택배 연동(N27·SR-264), 반품 상태(SR-266).

## 수용 기준

- [ ] 허용 전이표에 없는 전이 요청은 409와 기존 오류 봉투로 거부된다
- [ ] 모든 상태 변경이 ORDER_STATE_HISTORY에 한 행씩 남는다
- [ ] 기존 주문 데이터(PLACED·DONE 포함)가 목록·상세·CSV에서 깨지지 않고 한글 라벨로 표시된다
- [ ] 기존 취소(SR-218 사유 필수)·목록 필터(SR-205·209)·CSV(SR-223) 테스트가 통과한다
