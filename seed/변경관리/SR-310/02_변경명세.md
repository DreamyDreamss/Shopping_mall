# SR-310 변경명세

## AS-IS → TO-BE 비교

### UIS-CMN-002 (공통 컴포넌트 — shop-web)

- AS-IS: 스펙 파일 없음(신규 산출물). `_impact.json`의 `new_specs`에 `UIS-CMN-002`(공통 컴포넌트, domain=common, module=shop-web)로만 등재돼 있고, `affected.uis: []`로 기존 UIS 화면설계서 대상은 없음. 요구사항 배경에 따르면 현재 화면은 버튼·입력을 화면마다 새로 만들어 모양과 상태 표기가 제각각이며, 공유되는 공통 컴포넌트 세트가 없음.
- TO-BE: shop-web에 아래 공통 컴포넌트를 신설한다(모두 SR-309 디자인 토큰만 참조). 요구사항·확정 문답 근거로 다음을 담는다 —
  - **Button**: 3종 — 주(검정 채움) · 보조(흰 바탕 회색 테두리) · 구매(파랑→보라 그라데이션). 상태별 스토리: 각 종별 기본·호버·포커스·비활성·로딩.
  - **TextInput**: 상태별 스토리 — 기본·포커스·오류·비활성.
  - **QuantityStepper**: `−` / 수량 / `+` 구성. 최솟값·최댓값 경계에서 버튼 비활성화, 범위 밖 직접 입력값은 경계로 보정. 상태별 스토리 — 중간값·최솟값·최댓값·직접입력 보정.
  - **Badge**: 5종 — TV상품(검정) · 무료 배송 · 무이자 N(테두리형) · LIVE(카운트다운 슬롯) · 할인율(빨강). 5종 각각 스토리.
  - **Tabs**: 스티키(스크롤 고정) · 스와이프 전환. 상태별 스토리 — 기본·스티키 고정.
  - **BottomSheet**: 구매 시트 용도. 열릴 때 포커스 트랩, Esc·닫기로 닫힘, 닫힌 뒤 트리거 요소로 포커스 복귀. 상태별 스토리 — 열림·닫힘.
  - **PopupCarousel**: 이미지 팝업 캐러셀, '오늘은 그만 보기' 옵션 포함. 상태별 스토리 — 1/5·마지막·오늘은 그만 보기.
  - **Toast**: 최대 3개 동시 노출, 초과 시 가장 오래된 것부터 제거. 상태별 스토리 — 1개·3개·초과 시 제거.
  - **Skeleton**: 상태별 스토리 — 카드·리스트.
  - **EmptyState**: 가운데 라인 아이콘 + 한 줄 안내 + 테두리 버튼 + 하단 추천 레일 슬롯(벤치마크 bench/screenshot-10 빈 장바구니 구성과 동일).
  - **ErrorState**: 원형 느낌표 아이콘 + '이용에 불편을 드려 죄송합니다.' + 보조 문구 + [홈으로](테두리 버튼) · [돌아가기](검정 버튼)(벤치마크 bench/screenshot-11 404 구성과 동일).
  - 공통 키보드 조작: BottomSheet·PopupCarousel 모두 포커스 트랩·Esc 닫기·닫힌 뒤 포커스 복귀.
  - 산출물: 위 11개 컴포넌트 + 상태별 스토리(Storybook) + 컴포넌트 단위 테스트. UIS 대상은 이 문서(UIS-CMN-002 공통 컴포넌트 규격) 1건.

## 제외(변경 없음 명시)

- 기존 화면 교체(리스킨) — SR-322·326에서 다룸. 이번 SR은 컴포넌트를 추가만 하고 기존 화면에 끼우지 않음(확정 문답 scope_freeze).
- 기존 컴포넌트(DeliveryBadge·LoginForm·Order* 등) — 동작·모양·테스트 전부 불변, 이번 SR에서 손대지 않음(확정 문답 regression_keep).
- 데이터 연동 — 제외(확정 문답 scope_freeze).
- 팝업 운영 데이터 — SR-339에서 다룸, 이번 SR은 PopupCarousel 컴포넌트 자체만(확정 문답 scope_freeze).
- 오프라인 배너(SR-289 잔여) — 제외(확정 문답 scope_freeze).
- 백엔드(shop-api) 변경 — 없음(확정 문답 scope_freeze, db_ripple, db_migration).
- 타 도메인 테이블·집계(정산·통계류) — 파급 없음(확정 문답 db_ripple: "화면 컴포넌트 SR이라 DB·테이블 변경이 없다").
- 데이터 이관·백필 — 대상 없음(확정 문답 db_migration).
- 사용자 진입 화면 — 없음, 개발자용 스토리북 컴포넌트 문서뿐(확정 문답 scr_entry, scr_scope).

## 회귀 범위

- 기존 화면·기존 컴포넌트(DeliveryBadge·LoginForm·Order* 등)의 동작·모양·테스트 전부 불변 — 새 컴포넌트는 추가만 하고 기존 화면에 끼우지 않는다(확정 문답 regression_keep).
- 스토리북 빌드 성공 유지, 기존 스토리 콘솔 오류 0건 유지(확정 문답 regression_keep).
- 새 컴포넌트는 SR-309 디자인 토큰만 참조한다(요구사항 범위·수용 기준).
- 컴포넌트 단위 테스트를 신설하고 기존 화면 테스트는 그대로 통과해야 한다(요구사항 수용 기준).

## 롤백 요지

이 SR의 변경은 shop-web에 신규 컴포넌트 파일(Button·TextInput·QuantityStepper·Badge·Tabs·BottomSheet·PopupCarousel·Toast·Skeleton·EmptyState·ErrorState)과 각 컴포넌트의 상태별 스토리·단위 테스트를 추가하는 형태이며, 기존 화면·컴포넌트는 참조하거나 교체하지 않는다. 롤백은 역순으로: (1) 신설한 컴포넌트별 단위 테스트 파일을 제거하고, (2) 컴포넌트별 `*.stories.tsx` 상태 스토리 파일을 제거하고, (3) 위 11개 신규 컴포넌트 구현 파일을 제거한다. 기존 화면은 이번 SR의 컴포넌트를 조립하지 않으므로(적용은 SR-322·326 등 리스킨 SR의 몫) 롤백 시 기존 화면·기능에 미치는 영향은 없다. DB·백엔드 변경이 없으므로 DB 롤백 절차는 불필요하다.
